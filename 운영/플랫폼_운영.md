# 플랫폼 운영 메모

> 마스토돈, 디스코드, 자체 호스팅 커뮤니티 팩 사이트를 어떻게 역할 분담할지 정리하는 문서.  
> 현재 기준은 `違法人類 :: 여죄(餘罪)`의 운영 형태입니다.

---

## 0. 운영 전제

### 커뮤니티 정보

- 제목: `違法人類 :: 여죄(餘罪)`
- 장르: 현대 판타지 / 근미래 이능력 / 다극 진영극
- 러닝 방식: 혼합형
  - 장문 RP
  - 단문 RP
  - 비주얼 로그
  - 조사/전투 이벤트
- 예상 규모: 10~25명
- 핵심 운영 원칙:
  - 공동 집필
  - 특정 인물 중심 서사 지양
  - 다극 진영
  - 회색지대
  - 일상 30% / 시리어스 70%

---

## 1. 현재 고려 중인 구조

### 메인 RP 플랫폼

- 마스토돈

### 기능/편의 시스템

- 자체 호스팅 커뮤니티 팩 사이트

### 보조 소통

- 디스코드

### 운영 결론 초안

`마스토돈 + 자체 호스팅 커뮤니티 팩 사이트`를 중심으로 운영한다.  
디스코드는 메인 RP 플랫폼이 아니라 운영 보조, 알림, 실시간 이벤트 보조 채널로 제한한다.

## 3. 마스토돈의 역할

### 맡길 것

- 캐릭터 일상 RP
- 타임라인형 교류
- 짧은 대화
- 긴 로그 링크 공유
- 개인 서사 진행
- 캐릭터 간 관계 형성
- 사건 이후 반응 RP

### 장점

- 트위터형 타임라인에 가까워 자캐 커뮤니티 문화와 잘 맞는다.
- 비동기 RP에 적합하다.
- 접속 시간대가 달라도 게시글을 따라가기 쉽다.
- 단문/장문/이미지 로그를 모두 허용하기 좋다.

### 단점

- 신규 러너에게 사용법 안내가 필요하다.
- 편의 기능이 디스코드보다 비직관적일 수 있다.
- 조사/전투 수치 처리는 별도 시스템이 필요하다.

### 운영 규칙으로 정해야 할 것

- 캐릭터 계정 생성 방식
- 공개/비공개 게시글 기준
- 멘션 RP 규칙
- 로그 태그
- 사건 태그
- 스포일러/비공개 정보 처리
- 멸칭 `위법인류` 사용 가능 범위
- 수위 및 갈등 RP 매너라인

- 조사 결과 기록

- 세계관 문서
- 사건 연표
- 관계도
- 러닝 기록 백업

### `違法人類 :: 여죄`에 맞춘 사이트 기능 후보

- 사건 참여 이력

- 부상/폭주 기록
- 감시도 변동

#### 3. 사건 파일

- 사건명
- 발생 구역
- 관련 세력

### 주의할 점

- 사이트 기능을 너무 많이 만들면 오픈 전에 지칠 수 있다.
- 1차 오픈에는 필수 기능만 구현한다.
- 멋진 UI보다 운영에 실제로 필요한 기능을 먼저 만든다.

### 1차 필수 기능

- 공지/세계관 문서

### 2차 확장 기능

- 관계도

- 세력 평판

## 5. 디스코드의 역할

### 맡길 것

- 운영진 회의
- 빠른 문의
- 공지 알림
- 이벤트 알림
- 조사/전투 실시간 진행 보조
- 비상 공지
- 서버 장애 시 대피 채널
- 자료 백업 링크 공유

### 맡기지 않는 것이 좋은 것

- 메인 RP
- 모든 일상 교류
- 러너 간 관계 형성의 중심
- 주요 세계관 문서의 유일한 보관 장소

### 이유

디스코드는 실시간성이 강해 접속 시간대 차이가 큰 러너가 소외될 수 있다.  
특히 `違法人類 :: 여죄`는 혼합형 러닝이며, 단문/장문/비주얼 로그가 모두 허용되므로 메인 RP는 비동기 플랫폼인 마스토돈이 더 적합하다.

## 6. 러닝 흐름 초안

### 평상시

1. 러너는 마스토돈에서 캐릭터 RP를 진행한다.
2. 장문 로그나 그림 로그는 마스토돈에 업로드하거나 외부 링크를 공유한다.
3. 사이트에는 프로필, 상태, 공지, 세계관, 사건 기록이 정리된다.
4. 디스코드는 알림과 문의에만 사용한다.

### 조사 이벤트

1. 사이트 또는 디스코드에 조사 공지가 올라온다.
2. 러너는 조사 참여 여부와 행동을 제출한다.
3. 결과는 사이트의 사건 파일에 기록된다.
4. 캐릭터 반응 RP는 마스토돈에서 이어간다.

### 전투 이벤트

1. 운영진이 전투 상황을 공지한다.
2. 전투 수치와 상태는 사이트에서 관리한다.
3. 전투 선언은 마스토돈 또는 디스코드 임시 채널 중 하나로 통일한다.
4. 결과와 부상, 감시도, 후폭풍은 사이트에 기록한다.
5. 이후 캐릭터 반응은 마스토돈에서 진행한다.

## 9. 운영 부담 줄이기 원칙

### 반드시 지킬 것

- 모든 기록을 운영진이 수동으로 옮기지 않는다.
- 러너가 직접 입력할 수 있는 것은 사이트 폼으로 처리한다.
- 전투 수치는 너무 세분화하지 않는다.
- 감시도/평판 등 추가 시스템은 1차 오픈 필수 기능으로 넣지 않는다.
- 문서는 공개용/운영진용을 분리한다.
- 1기 내용을 과하게 요구하지 않는다.

### ADHD 대응 운영 방식

- 한 번에 모든 시스템을 완성하지 않는다.
- 1차 오픈에 필요한 것과 나중에 멋있게 만들 것을 분리한다.
- `아이디어 인박스`에 넣은 것은 당장 구현하지 않아도 된다.
- 매 작업은 초안 → 검토 → 수정 → 정리로 나눈다.
- 사이트 기능은 "운영에 필요한 최소 단위"부터 만든다.

## 11. 현재 결론

현재 구조는 다음이 가장 안정적이다.

```text
마스토돈 = 메인 RP
자체 사이트 = 신청서/프로필/세계관/스탯/전투/기록
디스코드 = 알림/문의/운영진 회의/실시간 이벤트 보조
```

이 구조는 비동기 RP를 보장하면서도, 자체 사이트를 통해 자캐 커뮤니티 특유의 기능적 불편함을 보완할 수 있다.  
디스코드는 편의성이 높지만 메인 플랫폼으로 삼으면 시간대 차이가 큰 러너가 소외될 수 있으므로, 보조 역할로 두는 것이 좋다.
