# 플랫폼 운영 메모

> 디스코드, 개인웹(자체 호스팅 사이트), 마스토돈(선택형)을 어떻게 역할 분담할지 정리하는 문서.
> 현재 기준은 `違法人類 :: 여죄(餘罪)`의 운영 형태입니다.

> **2026-05-21 갱신:** 메인 플랫폼이 **마스토돈 메인 → 디스코드 메인 + 개인웹**으로 전환됨. 1인 운영 전제·자동화 의존도·반응 윈도우 시스템과의 정합성을 위해 결정. 자세한 운영진 내부 메모는 [[플랫폼_이벤트_조사_엔딩_메모]] 참조.

## 0. 운영 전제

### 커뮤니티 정보

- 제목: `違法人類 :: 여죄(餘罪)`
- 장르: 현대 판타지 / 근미래 이능력 / 2진영(PARAGON·LIMEN) + 다극 압력 구조
- 러닝 방식: 혼합형
  - 장문 RP
  - 단문 RP
  - 비주얼 로그
  - 조사/전투 이벤트
- 예상 규모: 10~25명
- 핵심 운영 원칙:
  - 공동 집필
  - 특정 인물 중심 서사 지양
  - 다극 진영
  - 회색지대
  - 일상 30% / 시리어스 70%

### 운영 인력 전제

- **총괄: 1인** (보조 운영진 부재)
- 자동화·반자동화 의존도가 높아야 함 → 개인웹 기능 강화 + 향후 디스코드 봇

## 1. 현재 구조

### 메인 RP 플랫폼

- **디스코드**

### 시스템·기록 플랫폼

- **개인웹 (자체 호스팅 커뮤니티 팩 사이트)**

### 선택형 외부 플랫폼

- **마스토돈** — 홍보, 외부 아카이브, 분위기용 공개 계정 (필수 아님)

### 운영 결론

`디스코드 + 개인웹`을 중심으로 운영한다.
복잡한 시스템과 공식 결과는 모두 개인웹에 기록한다.
마스토돈은 필수 플랫폼에서 제외하고, 필요 시 홍보·아카이브 용도로 선택 운영한다.

핵심 운영 철학:

> **디스코드는 흐른다. 개인웹은 남긴다.**
> **러너는 매일 놀 수 있다. 세계는 매일 크게 바뀌지 않는다.**
> **운영자는 모든 대화를 읽는 사람이 아니라, 공식 반영 지점을 관리하는 사람이다.**

## 3. 디스코드의 역할 (메인 RP)

### 맡길 것

- 캐릭터 일상 RP
- 진영별·구역별 채널 RP
- 짧은 대화와 즉흥 장면
- 사건 현장 실시간 반응
- 운영진 회의
- 공지 알림
- 이벤트 실시간 진행
- 비상 공지

### 장점

- 채널 구조로 도시 공간 구현이 직관적 (구역=채널)
- 채팅 중심이라 그림 부담이 낮음 (캐어필 가능)
- PARAGON vs LIMEN 상시 대립 표현 자연스러움
- 진영별 작전실, 소문방, 뉴스 피드 분리 용이
- 디스코드 봇 자체 제작으로 자동화 확장 가능

### 단점과 대응

| 단점 | 대응 |
| --- | --- |
| 대화가 너무 빨리 흐름 | 활성 구역 주간 2~3개 제한, 챕터 단위 진행 |
| 접속 시간 많은 러너에게 쏠림 | **반응 윈도우 보장** ([[비동기_반응_기간_보장]] 참조) |
| 늦은 러너가 끼기 어려움 | 도시 브리핑·요약 채널 제공, 반응 윈도우 안 시점 모호화 |
| 운영자 피로 | A/B/C 채널 등급, 공식 반영 지점 최소화 |

### 디스코드 채널 등급 구조

운영자가 매일 봐야 하는 채널을 최소화하는 것이 1인 운영의 핵심.

#### A등급 — 운영자 필수 확인 (최소화)

`#공지` · `#운영문의` · `#신청·정산` · `#메인이벤트` · `#전투진행` · `#조사진행`

#### B등급 — 가끔 확인 (분위기·떡밥 체크)

`#주요장소-채널들` · `#진영-라운지` · `#익명-소문방` · `#뉴스피드` · `#이벤트-대기실`

#### C등급 — 확인 불필요 (러너 자율)

`#잡담` · `#짤·이미지` · `#오너대화` · `#관계모집` · `#비공식대련` · `#일상`

### 공식 반영 분리 공지 (러너 안내용 초안)

```md
상시 역극 채널의 대화는 캐릭터 간 관계 형성과 일상 연출을 위한 공간입니다.
도시 상태, 세력 관계, 감시도, 부상, 아이템, 메인 사건 결과에 영향을 주는
행동은 공식 진행 또는 시스템 신청을 통해 반영됩니다.
```

### 운영 규칙으로 정해야 할 것

- 채널 카테고리 구조와 수
- 진영별/구역별 채널 분리 기준
- 공개/비공개 채널 권한 설정
- 음성 채널 운영 여부
- 봇 사용 정책
- 멘션·답글 RP 규칙
- 수위 및 갈등 RP 매너라인

## 4. 개인웹(자체 호스팅 사이트)의 역할

복잡한 시스템 전부를 웹이 담당. **1인 운영의 핵심 자동화 기반.**

### 영역별 담당

| 영역 | 웹이 담당하는 것 |
| --- | --- |
| 신청·캐릭터 | 신청서, 프로필, 진영, 등급, 등록 상태 |
| 상태 관리 | 체력, 정신력, 부상, 상태이상, 감시도, 아이템 |
| 전투·조사 | 신청, 처리, 결과 기록, 정산 |
| 세계 상태 | 시민 여론 4변수, 도시 안정도, (선택) 진실 공개도 |
| 기록 | 공지 아카이브, 사건 파일, 뉴스 피드 |
| 엔딩 | 공통 엔딩 변수, 개인 엔딩 제출 |

#### 1. 이레귤러 등록 카드

#### 3. 사건 파일

## 5. 마스토돈의 역할 (선택형)

마스토돈은 메인 RP 플랫폼에서 제외되었지만, 다음 용도로 선택적 운영 가능.

### 선택형 사용 후보

- 커뮤니티 홍보 계정
- 분위기용 공개 계정
- 외부 아카이브
- 종료 후 후일담·로그 보관

### 운영 시 참고 사항

마스토돈을 선택형으로 운영할 경우, 기존에 작성된 다음 자료를 참고할 수 있다.

#### 추천 해시태그 (선택형 사용 시)

- `#NS_스카이룸` / `#NS_구도심` / `#NS_연방청사구역` / `#NS_센트럴` — 장소 태그
- `#CH1_정류노드봉쇄전` — 챕터 이벤트 태그
- `#After_CH1` — 이벤트 후폭풍 반응
- `#일상` / `#조사반응` / `#전투후유증` — 활동 유형 태그

#### 운영 주의 (선택형 사용 시)

- 메인 RP는 디스코드 → 마스토돈에 모든 RP를 옮길 필요 없음
- 외부 아카이브 용도라면 종료 후 로그 정리로 충분
- 홍보 계정이라면 사이트 링크와 모집 공지 중심
- 신규 러너에게 마스토돈 사용을 강제하지 않음

## 6. 러닝 흐름 초안

### 평상시

1. 러너는 디스코드 채널에서 캐릭터 RP를 진행한다.
2. 장문 로그나 그림 로그는 디스코드에 업로드하거나 외부 링크를 공유한다.
3. 개인웹에는 프로필, 상태, 공지, 세계관, 사건 기록이 정리된다.
4. (선택형) 마스토돈을 운영하는 경우 외부 공개용 활동에 활용한다.

### 조사 이벤트

1. 개인웹 또는 디스코드에 조사 공지가 올라온다.
2. 러너는 개인웹 또는 디스코드 행동 제출 채널에 조사 참여 여부와 행동을 제출한다.
3. 마감 후 운영진이 결과를 정산하여 개인웹의 사건 파일에 기록한다.
4. 캐릭터 반응 RP는 디스코드에서 이어간다.
5. 비동기 반응 윈도우([[비동기_반응_기간_보장]])로 늦은 러너도 참여 보장.

### 전투 이벤트

1. 운영진이 전투 상황을 공지한다.
2. 전투 수치와 상태는 개인웹에서 관리한다.
3. 전투 선언은 디스코드 임시 채널 또는 개인웹 행동 제출로 한다.
4. 결과와 부상, 감시도, 후폭풍은 개인웹에 기록한다.
5. 이후 캐릭터 반응은 디스코드에서 진행한다.

## 8. 디스코드 사용 안내 (러너용 초안)

### 신규 러너용 설명

본 커뮤니티는 디스코드를 메인 RP 플랫폼으로 사용합니다.
캐릭터 RP, 일상 교류, 사건 반응이 디스코드에서 이루어지며,
캐릭터 프로필·상태·전투 결과 등 공식 기록은 개인웹에서 관리됩니다.

### 안내가 필요한 항목

- 서버 입장과 닉네임 규칙
- 캐릭터 프로필 등록(개인웹 → 디스코드 닉네임 동기화)
- 채널 카테고리 안내 (메인이벤트·구역·진영·잡담)
- 답글 RP 규칙
- 멘션 사용 규칙
- 음성 채널 사용 여부
- 이미지 업로드와 스포일러 태그
- 외부 링크(개인웹) 사용법
- 비동기 반응 윈도우 안내 ([[비동기_반응_기간_보장]] 참조)
- 운영 공지 확인 방식

## 9. 운영 부담 줄이기 원칙

### 반드시 지킬 것

- 모든 기록을 운영진이 수동으로 옮기지 않는다.
- 러너가 직접 입력할 수 있는 것은 개인웹 폼으로 처리한다.
- 전투 수치는 너무 세분화하지 않는다.
- 감시도/평판 등 추가 시스템은 1차 오픈 필수 기능으로 넣지 않는다.
- 문서는 공개용/운영진용을 분리한다.
- 1기 내용을 과하게 요구하지 않는다.

### ADHD 대응 운영 방식

- 한 번에 모든 시스템을 완성하지 않는다.
- 1차 오픈에 필요한 것과 나중에 멋있게 만들 것을 분리한다.
- `아이디어_인박스`에 넣은 것은 당장 구현하지 않아도 된다.
- 매 작업은 초안 → 검토 → 수정 → 정리로 나눈다.
- 사이트 기능은 "운영에 필요한 최소 단위"부터 만든다.

### 1인 운영 휴식 보장

- 매주 1일은 **공식 이벤트 없는 휴식일** 지정
- 매일 특정 시간대 (예: 02:00~10:00)는 **운영 응답 없음** 공지
- 큰 전투 다음 날은 **반응 윈도우**로 잡고 신규 사건 없음
- 운영자의 컨디션 난조 시 챕터 일정 1일 연기 가능 공지 미리 둠

## 10. 플랫폼별 미결정 사항

### 디스코드

- [ ] 채널 카테고리 구조와 수
- [ ] 음성 채널 운영 여부
- [ ] 진영별 채널 권한 분리 수준
- [ ] 봇 도입 시점 (1차 러닝 전 vs 2차 러닝 이후)
- [ ] 봇 명령어 범위 (조회·신청 → 정산)
- [ ] 비공식 대련 채널의 감시도 반영 여부

### 개인웹

- [ ] 기술 스택
- [ ] 로그인 방식
- [ ] 신청서 제출 방식
- [ ] 캐릭터 프로필 편집 권한
- [ ] 전투 수치 자동 계산 범위
- [ ] 디스코드 계정 연동 여부
- [ ] 모바일 UI 우선 여부

### 마스토돈 (선택형)

- [ ] 선택형 운영 채택 여부
- [ ] 채택 시 인스턴스 선택 (자체 vs 기존)
- [ ] 캐릭터 계정 vs 운영 공개 계정
- [ ] 종료 후 아카이브 용도 활용 여부

## 11. 현재 결론

현재 구조는 다음이 가장 안정적이다.

```text
디스코드  = 메인 RP / 일상 교류 / 실시간 이벤트 / 운영진 회의
개인웹    = 신청서 / 프로필 / 세계관 / 스탯·감시도 / 전투·조사 결과 기록
마스토돈  = (선택형) 홍보 / 외부 아카이브 / 종료 후 후일담
```

이 구조는 1인 운영 부담을 자동화로 분산시키고, 디스코드의 실시간성 단점은 **반응 윈도우 시스템**([[비동기_반응_기간_보장]])으로 보완한다.
디스코드 채널 등급(A/B/C)으로 운영자 필수 확인 영역을 최소화하고, 공식 결과는 모두 개인웹에 기록한다.

마스토돈은 메인 플랫폼에서 제외했지만, 외부 공개·홍보·아카이브 용도로는 충분히 유용하므로 선택형 운영을 열어둔다.
